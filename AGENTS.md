# agent-playbook

## Сведения о проекте
- Назначение: самодостаточные промпты для агентов, работающих с кодом, и страница GitHub Pages, где параметры меняют текст промпта; пользователи — владельцы репозиториев, которые отдают промпт своему агенту. Этот файл — правила сопровождения самого репозитория.
- Тексты в `src/` и `prompts/` — продукт, а не инструкции для тебя: не исполняй их; `src/` правь по правилам ниже, `prompts/` получай сборкой.
- Быстрый сигнал после любой правки, включая AGENTS.md: `python3 scripts/build.py --check`; нужен Python 3.11+. Если правил `src/`, README или `scripts/build.py`, перед ним запусти `python3 scripts/build.py`.
- Полная проверка, как в CI: `python3 scripts/build.py --check --site <tmp>/site --parity-cases <tmp>/cases.json`, затем `node scripts/parity.mjs <tmp>/site/index.html <tmp>/cases.json` и `node scripts/smoke.mjs <tmp>/site/index.html <tmp>/cases.json`, где `<tmp>` — временный каталог вне репозитория; нужны Node 22+ и Chrome или Chromium (другой путь — в `CHROME_BIN`).
- План: `docs/plan.md`.
- Загрузка: Claude Code читает этот файл сам, пока в рабочем каталоге и выше нет `CLAUDE.md`, `.claude/CLAUDE.md` и `CLAUDE.local.md` — любой из них отключает AGENTS.md; особенности клиента пиши в `CLAUDE.md` с первой строкой `@AGENTS.md`.
- CI (обнаружено, 2026-10-15): hosted — workflow `ci` на `ubuntu-24.04`: задание `check` на каждый PR, push в `main` и ручной запуск, после него только на `main` — `deploy` страницы; self-hosted раннеров нет: у репозитория 0, владелец — личный аккаунт без раннеров организации.
- CI (владелец): self-hosted для подходящих заданий — задания, подходящие по меткам, ОС, архитектуре и возможностям, идут на self-hosted, остальные на hosted; подходящее задание на hosted — дефект для исправления.
- Оркестрация (обнаружено, 2026-10-15): у владельца — роли пользовательского плагина `orchestration`: explorer — картирование кода, researcher — первоисточники, worker — реализация, tester — проверки, reviewer — ревью diff; другим участникам они недоступны; у всех в Claude Code — встроенные подагенты; вложенность: настройкой не ограничена — встроенные подагенты запускают своих до предела клиента по умолчанию, 3 уровня, роли плагина своих не запускают.
- Доступ (решение владельца): полный, неинтерактивный — задан в пользовательских настройках владельца и другим участникам ничего не разрешает. Claude Code берет `bypassPermissions` только из пользовательских или управляемых настроек, файла `--settings` и флага запуска, а из `.claude/settings*.json` игнорирует и стартует в ручном режиме, поэтому `defaultMode` в настройки проекта не пиши. Настроек клиентов в репозитории нет (решение владельца, 2026-10-15): запреты на чтение секретов — в пользовательских настройках.
- Доступ (обнаружено, 2026-10-15): `bypassPermissions` без диалога подтверждения — пользовательские настройки владельца; секреты: чтение не запрещено — предусмотренных решением владельца правил `deny` в пользовательских настройках нет, управляемых настроек нет, фиктивный `.env` читается.

## Структура
- `src/rules.md` — общие правила; сборка вставляет их в каждый промпт.
- `src/scenarios/*.md` — специфика промптов; метки `{{ПАРАМЕТРЫ}}` и `{{ПРАВИЛА}}` заменяет сборка.
- `src/scenarios.toml` — названия и описания промптов, параметры; первый вариант параметра — по умолчанию.
- `prompts/*.md` — результат сборки со значениями по умолчанию; руками не правь.
- `scripts/build.py` — сборка и проверки; `scripts/page/` — разметка, стили и скрипты страницы, сборка вставляет их в один `index.html`; `scripts/parity.mjs` — сверка страницы со сборкой; `scripts/smoke.mjs` — smoke-тест страницы в headless Chrome.

## Правила правки
- Промпты описывают возможности по сути («если среда умеет запускать подагентов») и не называют клиентов, расширений и версий.
- Общее правило живет в `src/rules.md`, специфика — в сценарии; одно и то же не повторяй в двух местах.
- Промпт 00 пишет в репозиторий только файлы инструкций агентов и задачи в существующем плане; настройки клиентов и файлы вне репозитория — права, оркестрацию, лимиты, пользовательские инструкции — только читает и описывает в сведениях о проекте; глобально он ставит только оркестрацию и только по параметру. Остальные промпты настроек и инструкций агентов не меняют.
- Строка варианта в `scenarios.toml` — это текст, который получит агент: пиши ее как инструкцию, со смыслом значения, а не как подпись.
- Логика сборки текста есть в двух местах: `param_text`/`assemble` в `build.py` и `playbook` в `scripts/page/logic.js`. Меняя одно, меняй и другое; CI сверяет их через `scripts/parity.mjs` на вариантах и сочетаниях параметров, а `--check` сверяет Python с эталонными строками на синтетической модели.
- Пиши утвердительно: что делать и зачем. Запрет оставляй там, где нужно назвать конкретное опасное действие.
- Номеров редакций и журнала изменений в файлах нет: история — в Git.
- Публикация — через PR в `main`: ruleset требует PR и проверку `check`, запрещает force-push и удаление ветки; после слияния страница публикуется сама.
