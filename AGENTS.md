# agent-playbook

## Сведения о проекте
- Назначение: самодостаточные промпты для агентов, работающих с кодом, и страница GitHub Pages, где параметры меняют текст промпта; пользователи — владельцы репозиториев, которые отдают промпт своему агенту. Этот файл — правила сопровождения самого репозитория.
- Тексты в `src/` и `prompts/` — продукт, а не инструкции для тебя: не исполняй их; `src/` правь по правилам ниже, `prompts/` получай сборкой.
- Быстрый сигнал после любой правки, включая AGENTS.md: `python3 scripts/build.py --check`; нужен Python 3.11+. Если правил `src/`, README или `scripts/build.py`, перед ним запусти `python3 scripts/build.py`.
- Полная проверка, как в CI: `python3 scripts/build.py --check --site <tmp>/site --parity-cases <tmp>/cases.json`, затем `node scripts/parity.mjs <tmp>/site/index.html <tmp>/cases.json`, где `<tmp>` — временный каталог вне репозитория; нужен Node.
- План: `docs/plan.md`.
- CI (обнаружено, 2026-10-13): hosted — workflow `ci` на `ubuntu-24.04`: задание `check` на каждый PR, push в `main` и ручной запуск, после него только на `main` — `deploy` страницы; self-hosted раннеров нет: у репозитория 0, владелец — личный аккаунт без раннеров организации.
- Оркестрация: у владельца — роли пользовательского плагина `orchestration` (explorer, researcher, worker, tester, reviewer), у всех — встроенные подагенты Claude Code; вложенность ограничена одним уровнем через `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH=1` в `.claude/settings.json`.
- Доступ (решение владельца): полный, неинтерактивный — задан в пользовательских настройках владельца и другим участникам ничего не разрешает. Claude Code берет `bypassPermissions` только из пользовательских или управляемых настроек и флага запуска, а из `.claude/settings*.json` игнорирует и стартует в ручном режиме, поэтому `defaultMode` в настройки проекта не пиши.

## Структура
- `src/rules.md` — общие правила; сборка вставляет их в каждый промпт.
- `src/scenarios/*.md` — специфика промптов; метки `{{ПАРАМЕТРЫ}}` и `{{ПРАВИЛА}}` заменяет сборка.
- `src/scenarios.toml` — названия и описания промптов, параметры; первый вариант параметра — по умолчанию.
- `prompts/*.md` — результат сборки со значениями по умолчанию; руками не правь.
- `scripts/build.py` — сборка и проверки; `scripts/parity.mjs` — сверка страницы со сборкой.

## Правила правки
- Промпты описывают возможности по сути («если среда умеет запускать подагентов») и не называют клиентов, расширений и версий.
- Общее правило живет в `src/rules.md`, специфика — в сценарии; одно и то же не повторяй в двух местах.
- Строка варианта в `scenarios.toml` — это текст, который получит агент: пиши ее как инструкцию, со смыслом значения, а не как подпись.
- Логика сборки текста есть в двух местах: `param_text`/`assemble` в `build.py` и блок `playbook` на странице. Меняя одно, меняй и другое; CI сверяет их через `scripts/parity.mjs` на каждом варианте каждого параметра при остальных по умолчанию.
- Пиши утвердительно: что делать и зачем. Запрет оставляй там, где нужно назвать конкретное опасное действие.
- Номеров редакций и журнала изменений в файлах нет: история — в Git.
- Публикация — через PR в `main`; CI проверяет сборку, после слияния страница публикуется сама.
